# Package tests

## Self-contained smoke test (run after installing the package)

`smoke_integration.py` needs no repository or P013 fixtures. It copies the package to an isolated folder and creates a separate project folder there. It then runs two short generic Hindi segments through every packaged stage:

1. Synthesis and timing.
2. Validation.
3. Combining.
4. A 270×480 preview render.
5. Procedural assets.
6. The mix and a stream-copy mux.

Along the way it checks:

- That the same narration hash flows through every stage.
- That the final MP4 is valid.
- Output protection and provenance.
- That unsupported styles and locales fail explicitly.
- Documented commands and links.
- That the installed package is left unchanged.

```
python -I scripts/tests/smoke_integration.py --runtime <kokoro runtime.json> [--work <folder outside the package>]
```

It writes results to `<work>/smoke-results.json`, never into the package.

## Preflight tests (self-contained)

`python -I scripts/tests/test_doctor.py --runtime <kokoro runtime.json> [--mithi-runtime <mithi runtime.json>] [--work <dir>]` runs the doctor from an isolated copy. It checks the available route, the distinction between planned, candidate and validated statuses, five unsupported combinations, missing FFmpeg and FFprobe, missing or unconfigured or in-package runtimes, read-only behaviour and package immutability. With `--mithi-runtime` it also checks that te-IN reports synthesis available, word timing unavailable (`word-timing-unavailable`, not READY), and that a non-WSL Mithi runtime is refused.

`python -I scripts/tests/test_preferences.py --runtime <kokoro runtime.json> [--work <dir>]` runs the preference store from an isolated copy. It checks defaults with no hardcoded language or style, persistence, refusal to overwrite, partial updates, request precedence, 11 invalid values, capability checks through the doctor, schema versions and corrupt stores, confirmed reset with backup, and package protection.

`python -I scripts/tests/test_project.py [--work <dir>]` exercises the project ledger with generic artifacts. It checks initialization, overwrite protection, dependency enforcement, completion evidence, no repeat of completed stages, resume after interruption, failed and blocked reasons, invalidation by artifact corruption or configuration change, approval gates and their revocation, the single-writer lock, corrupt manifests and package immutability.

`python -I scripts/tests/test_narration_stage.py --runtime <kokoro runtime.json> [--work <dir>]` runs the script-to-narration stage with a short generic three-segment script. It checks 7 invalid scripts, multi-segment synthesis, duration measurement and hints, partial-revision reuse, bounded attempts, the active-process guard, corrupted-segment recovery, ledger completion, explicit unsupported and `auto` configurations, and package immutability.

`python -I scripts/tests/test_plan.py [--work <dir>]` exercises the creative-plan validator and cue resolver with synthetic, provider-neutral Kannada and English timelines (no TTS needed). It checks one- and three-shot plans, word, phrase, segment, shot-relative and offset anchors with exact sample results, repeated-word disambiguation, 13 rejections (ambiguous, missing, unmapped, out-of-range, unknown segment, cue bounds and order, provenance, unknown styles), style extensions, stale narration hashes and ledger invalidation, failed-stage evidence, and package immutability.

`python -I scripts/tests/test_render_plan.py [--work <dir>]` renders a short generic topic (`fixtures/plan-topic.js`, no speech timestamps) from a resolved plan over a synthetic toned narration (no TTS; needs Chromium and FFmpeg). It checks sample-exact cue times and shot bounds, a low-resolution MP4 with media checks, checkpoint reuse and invalidation, missing and unknown cues, conflicting shot boundaries, unverified and stale plans, a backend without the plan contract, a second backend consuming the same plan, cue times following a narration change, and package immutability.

`python -I scripts/tests/test_3d_explainer.py [--preview] [--work <dir>]` runs the 3D Explainer style (WebGL2 on CPU SwiftShader) on a compact gearbox fixture with Telugu captions, portrait and landscape. It checks cues, orbit camera moments, the exploded view, the `dolly` transition, 3D geometry and meshing mechanics, the pinned renderer flags, preflight through projected-bounds proxies, an optional preview, a contact sheet and package immutability. Preflight draws every frame in 3D, so this suite takes about four minutes.

`python -I scripts/tests/test_documentary.py [--preview] [--work <dir>]` runs the Documentary style with original procedural assets generated by FFmpeg and a verified asset manifest, Telugu captions, portrait and landscape. It checks cues, camera moments, the `dip` transition, refusals (manifest changed, unknown licence, synthetic asset without a provenance label), preflight, an optional preview, a contact sheet and package immutability.

`python -I scripts/tests/test_xray_explainer.py [--preview] [--work <dir>]` runs the X-Ray Explainer style on a compact two-gear fixture (`fixtures/xr-topic.js`, marked illustrative) with Telugu captions and labels, portrait and landscape. It checks cues, camera moments, the `sweep` transition, mechanics (pitch radius m·z/2, meshing spins at the inverse tooth ratio, invalid gears refused), preflight, an optional preview, a contact sheet and package immutability.

`python -I scripts/tests/test_kinetic_typography.py [--preview] [--work <dir>]` runs the Kinetic Typography style on a language-independent fixture (`fixtures/kt-topic.js`) in English and Telugu, portrait and landscape. It checks one cue per narration word, measured fit, the `shutter` transition, refusals of non-narration words and of typed reveal times, preflight, an optional preview, a contact sheet and package immutability.

`python -I scripts/tests/test_data_storytelling.py [--preview] [--work <dir>]` runs the Data Storytelling style on a compact fixture (`fixtures/ds-topic.js`, synthetic data labelled as such) with Kannada captions, labels and numerals. It checks cues, camera moments, the `bars` transition, portrait and landscape keyframes and preflight, data-integrity refusals with area and height proportionality, an optional 5.6 s preview, a contact sheet and package immutability.

`python -I scripts/tests/test_flat_science.py [--preview] [--work <dir>]` runs the Flat Science style on a compact photosynthesis fixture (`fixtures/fs-topic.js`) with Telugu captions and labels. It checks cues, camera moments, the `magnify` transition, portrait and landscape keyframes and preflight, an optional 5.6 s preview, a contact sheet and package immutability.

`python -I scripts/tests/test_whiteboard.py [--preview] [--work <dir>]` runs the Whiteboard style on a compact synthetic fixture (`fixtures/wb-topic.js`). It checks speech-driven drawing cues, camera moments, the `erase` transition, English portrait and landscape and a Hindi caption variant, preflight with the empty-caption check, an optional 5.6 s preview, a contact sheet and package immutability.

`python -I scripts/tests/test_richness.py [--preview] [--frames 60] [--work <dir>]` renders the P018.3 richness fixtures, a Telugu volcano (Paper) and English wireless charging (Tech), as plain and rich versions of the same composition. It checks speech cues, full-cadence preflight of the rich version, deterministic baked textures, plain-versus-rich full-resolution frame cost (best of two), optional 540×960 previews, before/after sheets and package immutability.

`python -I scripts/tests/test_presentation.py [--preview] [--work <dir>]` tests the opt-in full-bleed presentation (P018.2) on Paper Explainer and Tech Explainer with short Telugu and English fixtures. It renders before/after keyframes (framed versus full-bleed) and checks word-group captions with unchanged SRT/VTT, full-cadence preflight (Tech also in landscape), active-word timing against the timeline, caption-box stability, hook timing and whole-word highlight, label overlap detection, refusal of invalid specs, unchanged legacy framed installs, an optional 6 s preview and package immutability. It takes about a minute without `--preview`.

`python -I scripts/tests/test_tech_explainer.py [--preview] [--work <dir>]` runs the Tech Explainer style on a compact synthetic fixture (`fixtures/tech-topic.js`). It checks plan cues, captions, portrait and landscape keyframes, preflight in both orientations, camera moments, the focus and iris transitions, an optional 6 s preview, a contact sheet and package immutability.

`python -I scripts/tests/test_paper_kit.py [--work <dir>]` renders three keyframes of a compact generic fixture (`fixtures/kit-topic.js`) that uses every Paper Explainer kit helper, driven by resolved-plan cue IDs and camera moments. It checks the cue, layout and repeatability checks, the kit dissolve texture, camera moments in the render-plan contract, the `planCamera` view-count check, label-treatment validation and package immutability.

`python -I scripts/tests/test_preflight.py [--work <dir>]` runs the visual preflight on a generic fixture (`fixtures/preflight-topic.js`) whose keyframes pass but whose camera push clips a label on intermediate frames. It checks detection with frame and evidence, the corrected fixture passing, intentional overflow, transitions and camera movement not counted as defects, plan cue and camera timing, result binding, the renderer refusing failed and stale results, required-object and invalid-transform defects, an unsupported backend giving `incomplete`, the ledger refusing failed or incomplete evidence, and package immutability.

`python -I scripts/tests/test_captions.py [--work <dir>]` builds captions from synthetic kn, hi, te, ta and en-IN typography timelines (silent audio, no TTS). It checks exact Unicode text, SRT/WebVTT timing and text, «अलग-अलग» and conjuncts, repeated words, long captions with and without measured split points, disabled and subtitle-only configurations, portrait and landscape keyframes, caption-layout preflight for all five locales, line-limit overflow detection, stale and invalid artifacts, unmapped timing and package immutability. It says nothing about narration quality in those languages.

`python -I scripts/tests/test_qa.py [--work <dir>]` builds a short integration project (synthetic toned narration, resolved plan, captions, preflight, a 540×960 24 fps render and a narration-only mix) and runs the unified QA report. It checks missing, passed, failed, foreign, unsupported (no FFmpeg) and stale evidence, the final MP4 against the configuration, ledger completion, provenance marked missing, deliverables, that technical success grants no human or publication approval, the two explicit approvals, approval revocation and package immutability.

## Repository regression tests (developer use; need the source repository's P013 artifacts)

| Suite | Covers |
|---|---|
| `node scripts/tests/test-package.mjs` (source repository only; not in the release archive) | Renderer: flight keyframes byte-identical to P013.6, resume, horizontal, lock, locale/font, alternative backend, unsupported style |
| `python -I scripts/tests/test_mithi_timing.py [--sample <dir>]` | Mithi native word/phrase mapping from recorded raw evidence; 9 rejection codes; hyphenated words. With `--sample`, real Mithi audio through the combiner, ledger, repeated-word cue resolution and Telugu SRT/VTT captions; package immutability |
| `python -I scripts/tests/test_narration.py --runtime <json>` | P013 timelines validate; segment combining byte-identical; unsupported provider/locale/voice/script, including Mithi locale, voice, script and runtime-kind rejection; Hindi smoke |
| `python -I scripts/tests/test_audio.py` | The 8 sync tests (`test_sync.py`); mix and mux smoke; narration-only; provenance rejections; flight-mix measurement regression |

These suites write `test-*-results.json` next to themselves, so run them only in a development checkout.

## Package dependencies (none are bundled)

| Dependency | Needed by |
|---|---|
| Node 22+ (built-in WebSocket, `fetch`) | Renderer |
| Chromium-family browser | Paper Explainer backend |
| Python 3, standard library only | Narration front end, timeline, combining, mixer |
| FFmpeg and FFprobe | Encoding, mixing, validation |
| User-supplied Kokoro runtime: a Python environment with `kokoro-onnx` 0.6.1, `onnxruntime`, `soundfile`, `phonemizer`, `espeakng-loader` and `numpy`, plus the pinned model files | Hindi narration provider only |
