## 2. Experimental code to separate from topic content

1. **`experiments/E10/p013-flights/topic-opening.js`** mixes eight topic scenes with helpers that belong to the style: `hatch` paper fibre, `tufts` grass, the person and traveller builder, the boarding-pass builder and the luggage tag. Only the helpers that generalise should move into a Paper Explainer helper library. Every scene stays topic content.
2. **Renderer host page:** `render.mjs` loads `experiments/E06/paper-explainer/story.html`, which still embeds the flight and Wi-Fi demo scenes (`story-scenes.js`), and it imports `experiments/E05/render.mjs` for Chrome control. Both need a neutral, packaged host page and driver.
3. **Fixed locations and patterns:** the narration tools write into fixed E04 folders and use `sample-A.json` as their metadata template, with passage IDs restricted to `[A-Z]`. Timelines store repository-relative audio paths.
4. **Locale and voice baked in:** Hindi (`'hi'` eSpeak, `hf_alpha`, the Nirmala UI caption font) is hardcoded.
5. **One-off scripts:** `export-fullhd.ps1`, the storyboard-timing generator and the per-segment validator were one-off (scratchpad) scripts. They need to become cross-platform, project-relative tools.

## 4. How the agent should make a video (proposed workflow)

The agent owns all creative judgement. Tools do deterministic work and validation. Humans own the quality gates.

1. **Setup:** run `doctor` to check capabilities, then load or save preferences. Stop with a stage failure code if something required is missing.
2. **Research:** use user documents, plus web research only if the host allows it and the user opts in. Write a claim ledger: claim, source, quote summary, access date, confidence. Never invent sources. Unverified claims are marked as such.
3. **Script:** write native, conversational narration segments, each with a role (hook, mechanism, contrast, example, resolution). The hook's open question must be paid off. Estimate duration with measured rates: Hindi `hf_alpha` ran about 2.3 words/s in P013. After synthesis, revise the script until the measured length is within tolerance of the target.
4. **Narration:** synthesize each segment, capture timing, map words and phrases, validate and combine. Status stays `unreviewed`.
5. **Creative plan:**
   - Story-role map and motif ledger: which symbol stands for which spoken word.
   - Shots, each with phrase ranges, a visual purpose, a metaphor, a camera intention and a transition.
   - Cue **words** that the resolver turns into times.
   - Claim guardrails: what the visuals must never imply.

   These are free-form decisions with structured fields. There are no templates.
6. **Author the topic module:** original SVG art and motion on the engine contract, reusing the style helpers and earlier motifs. Iterate with `--keys-only`, then a **low-resolution full scan** of every frame (for example `--scale .25 --fps 10`) to catch mid-move problems like the P013.4 clipped label. Then a 540×960 preview.
7. **Sound:** write a mix spec with music and effects tied to plan events. Generate procedural or licensed assets with a manifest, mix, and run the sync check.
8. **Render and deliver:** checkpointed Full HD render, mux, validate, write the QA report, captions (SRT/VTT) and the human review packet. Stop for human review. Never claim publish-readiness.

## 5. Preferences, artifacts, recovery, gates

- **Preferences:** live outside the Skill package (a user config folder). A per-video override never changes the defaults.
- **Project folder** (outside the package): `inputs/`, `research/`, `script/`, `narration/`, `plan/`, `topic/`, `audio/`, `renders/{keys,scan,preview,final}/`, `qa/`, and `project.json` recording each stage's status, inputs, output hashes and evidence path.
- **Recovery:** already implemented for frames (manifest, hashes, invalidation, storage check). Extend the same pattern to stages: rerunning a stage is skipped when its input hashes match. Clear the narration, plan and render stages whenever their upstream changes.
- **Gates.**
  - *Automated*, all implemented somewhere and to be unified:
    - Media probe and full decode
    - Frame bounds, labels and text
    - Cues, transitions and caption coverage
    - Loudness and true peak
    - Narration sync
    - Asset provenance
  - *Human*, still open:
    - Native listening
    - Timing alignment
    - Visual and motion quality
    - Caption readability
    - Factual sources
    - Licensing

## 6. Portability (Codex, Claude Code, other Agent Skill hosts)

- **Package:** one core Skill (`SKILL.md` plus `references/` plus `scripts/`) per ADR-001. Entry points must be cross-platform Node or Python, with no PowerShell-only steps. Paths resolve from the Skill directory; projects and preferences live outside it.
- **Host needs:** shell execution; Node ≥ 22 (it uses the built-in WebSocket); Python 3 (system interpreter for tools, venv for Kokoro); FFmpeg/FFprobe; a Chromium-family browser; a Kokoro venv and model (about 340 MB); optionally WSL for Mithi. `doctor` must detect each one and report what's missing rather than assuming it.
- **Validated:** Windows 11 with Claude Code, plus Codex for earlier tasks. Skill discovery across hosts was only probed in E01. Linux and macOS are untested.

## 7. Outstanding blockers

- **Technical:**
  - Native timing exists only for Kokoro Hindi; the other four locales have no timing route.
  - No SRT/VTT export, and the caption hyphen break is unresolved.
  - Duration control is not automated.
  - One unexplained intermittent resume failure (P013.1).
  - Mid-move layout problems are caught only by a full render.
  - Captions rely on installed system fonts.
- **Human review:**
  - Hindi listening (E03)
  - Timing alignment (E04)
  - Visual and motion rubric (E06/E07)
  - Native caption and label review
  - Source verification (F01–F05)
  - Intelligibility check of the mix (F10)
- **Licensing:**
  - The rasterised Microsoft fonts (Nirmala UI, Segoe UI) need redistribution review; the alternative is an openly licensed Devanagari font, which needs approval as a new asset.
  - Kokoro model and voice terms follow the E03 records.
  - Chrome is used as a free local renderer.
  - All P013 art and audio are original procedural work.
