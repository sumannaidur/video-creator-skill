# P005.2 Mithi v2 Flash CPU experiment

The [pinned publisher release](https://huggingface.co/Oomni/mithi-v2-flash/tree/1fc0dd68496a2483508ec764d310146c41ff90be) identifies the BF16 model as 99.1M parameters and roughly 199 MB of weights. The publisher documents ten preset voices and Hindi, Kannada, Telugu, Tamil and English. English accent suitability requires a reviewer. The publisher's CPU instructions support four threads and Python 3.10 or later. Windows x64 is the experiment host.

The repository applies Apache-2.0 to weights and inference code and explicitly describes commercial use. No separate preset terms or output restriction for this private experiment were identified. Preset voice lineage, third-party notices and applicability to a particular commercial release remain open. The experiment uses the supplied presets without reference audio.

The [Windows Python 3.12 lock](../../../experiments/E03/mithi/dependency-lock.txt) resolved 94 packages, including explicitly mapped PyTorch 2.9.1+cpu from the official PyTorch CPU index, an upstream spaCy English pipeline wheel and ordinary dependencies from PyPI. The existing Kokoro environment and audio were not used by the installer.

The runner loads the pinned local implementation, encoder, configurations and safetensors. It uses native dataset text, upstream normalization and fixed preset voices. Each passage runs in a fresh CPU process with four intra-op threads, one inter-op thread, Python socket auditing and Transformers offline settings. The monitor enforces the sampled 2 GiB process-tree ceiling, 2 GiB available system RAM floor and 180-second timeout. WAV validation reuses the Kokoro experiment's FFprobe, FFmpeg and PCM checks.

## Result

**Blocked by Windows Application Control during Hindi A phonemizer initialization.** The model loaded and the application reached synthesis, then the upstream frontend imported Misaki's English G2P even for Hindi. Its spaCy dependency failed to load `transition_system.cp312-win_amd64.pyd` with `ImportError: DLL load failed while importing transition_system: An Application Control policy has blocked this file.` The installed file's SHA-256 is `BB6C04B97B03FA765EB548A13D5614D519F37F98C91C23C7B897BEC751DD417B`. See the [traceback](../../../experiments/E03/mithi/hi-IN-A-stderr.txt) and [monitor record](../../../experiments/E03/mithi/hi-IN-A-monitor.json). The process exited 1 after 117.113 s with no WAV and no resource cutoff. Peak sampled process-tree memory was 771.8 MiB. Available RAM was 5.535 GiB before, 4.801 GiB minimum sampled, and 5.531 GiB after. Available RAM and free D: storage before installation were 4.973 GiB and 133.70 GiB.

All ten [model files](../../../experiments/E03/mithi/model-manifest.json) were verified against published SHA-256 or Git blob IDs. The verified required files totaled 208,472,482 bytes. The download recovered from slow transfers through bounded ranges. Total wire bytes including retries were not measured. The final external footprint was 1,965,695,059 logical bytes, including 882,966,097 bytes in the venv, 873,870,662 in the cache, 208,830,932 in the model directory including retained range fragments, and 27,368 in temp. `uv pip check` confirmed all 94 installed packages were compatible by metadata. The [dependency inventory](../../../experiments/E03/mithi/dependency-manifest.json) records published package license metadata where present. The [installation evidence](../../../experiments/E03/mithi/install-evidence.txt) records wheel preparation and installation.

Stage A used the existing Hindi A speech text and preset female narrator `charvi`. The blocked run has no completed synthesis latency, duration, RTF, audio properties or offline inference pass. Hindi B and the Kannada, Telugu, Tamil and English passages were gated on Hindi A and remain untested. No blind Mithi listening IDs were assigned. The verified Kokoro passages remain the only measured Hindi comparison, with synthesis of 7.580 / 5.720 s, duration of 7.425 / 8.925 s, RTF 1.021 / 0.641, and peak sampled memory of 556.4 / 580.3 MiB. Neither candidate has human listening or commercial publishing clearance.

The smallest next step is for the device administrator to review the pinned spaCy wheel and the Application Control event, and identify an approved runtime build under the existing policy. Once approved, resume with Hindi A using the retained verified model. No policy setting was changed.

## P005.2A policy diagnosis

On 25 November 2026, the Windows Code Integrity Operational log showed paired events 3077 and 3033 for the Mithi failure at 13:56:28. The enforcement event reported policy `VerifiedAndReputableDesktop` and status `0xc0e90002`. Correlated 3089 records reported zero signatures, and the installed extension's Authenticode status was `NotSigned`. Other Python native extensions also appeared in recent 3077 records. Their presence does not establish that every spaCy extension is blocked. The records establish active policy enforcement. They do not identify who configured or manages the policy.

The isolated installation contains spaCy 3.8.18, required directly by the experiment input and transitively by Misaki 0.9.4's English extra. The affected path relative to site-packages is `spacy/pipeline/_parser_internals/transition_system.cp312-win_amd64.pyd`. The official [PyPI wheel](https://pypi.org/project/spacy/3.8.18/) is `spacy-3.8.18-cp312-cp312-win_amd64.whl` (15,190,040 bytes, SHA-256 `8b3fe34abbd91526fc6b719672fa8c7a5e64fe54899f85aa5404a588ca3f1251`). A verification copy was read into memory and matched the PyPI wheel hash. All 46 native wheel files matched their installed bytes, including the blocked module hash above. This rules out corruption in those compared native files. The [spaCy source license](https://github.com/explosion/spaCy/blob/master/LICENSE) is MIT.

The [pinned Mithi implementation](https://huggingface.co/Oomni/mithi-v2-flash/blob/1fc0dd68496a2483508ec764d310146c41ff90be/run.py) initializes `misaki.en` and eSpeak together even for Hindi. English G2P contributes to mixed-text handling, so an eSpeak-only replacement has no established input equivalence. The publisher documents a CPU path but provides no alternate frontend in this release. The spaCy project has an [open request for Authenticode-signed Windows wheels](https://github.com/explosion/spaCy/issues/14078). No compatible build with evidence of permission under the existing policy was identified. Installing or probing arbitrary older builds was outside the remediation gate.

No dependency or phonemizer change was made. Phonemizer initialization remains blocked, Hindi A has no WAV, and the other samples remain untested. The retained lock, environment, model and prior evidence are ready to resume if an authorized compatible Windows build is identified. An approved separate CPU host is another option, subject to verifying its dependencies and reporting its results as a separate hardware baseline.

## P005.2C.2 — WSL CPU generation

Seven short samples passed on Ubuntu 24.04 WSL 2 using the owner-prepared Python 3.12.3 and PyTorch 2.9.1+cpu environment. The launcher reused the existing Windows-mounted model data read-only and checked all ten files against the pinned manifest before each run. This is a separate execution environment from the native Windows failure. The initial launcher passed a stray carriage return in the passage ID and stopped before inference. The Linux shell launcher passes arguments directly and resolved that issue.

The synthesis runner used four intra-op CPU threads and one inter-op thread. Each process was monitored independently and each WAV passed FFprobe, full FFmpeg decoding and non-silence checks before the next process started. All files are 24 kHz mono PCM16 and had zero samples at clipping rails. All seven SHA-256 hashes were independently rechecked. Inference used pinned local assets, offline loading flags and a Python socket audit guard. OS-level network isolation was not tested.
