# P004 — Local multilingual voice research

Researched **2026-11-25** from official model cards, repositories, and license texts. No checkpoint was downloaded or run. Published samples and claims are **external evidence**, not listening or benchmark results on this machine. See [E02 hardware](../experiments/E02-hardware-assessment.md): 4-core/8-thread CPU, 16 GiB installed but ~2.5 GiB free at inspection, integrated Iris Xe, 134 GiB free on D:, no active Python TTS packages. The provisional first-test incremental RAM budget is ~1 GiB, not a model-specific limit.

## Narration evaluation boundary

Evaluate the **script** separately for hook, clarity, cultural appropriateness, natural sentence structure, and narrative progression. Hold the script constant when comparing synths. Evaluate audio for pronunciation, intelligibility, rhythm, prosody, emotion, emphasis, meaningful pauses, transitions, accent, consistency, long-form stability, code-switching, names, locations, numbers, dates, currency, abbreviations, units, and technical terms. Script rewrites can improve final narration, but cannot be credited as model quality gains in controlled comparison.

## Python and implementation-independent provider boundary

The active `python` 3.14.3 lacks pip; a separate `pip` targets Python 3.13. Model cards may require older Python (IndicF5 documents 3.10; Vakyansh 3.7). For approved future experiments, use a per-model isolated environment with an explicitly checked interpreter, pinned requirements/checkpoint revision, hashes, and a saved installation log. Standard `venv` is a candidate; `uv` or Conda may help incompatible requirements but neither is selected or installed. Avoid global package changes. First confirm Windows CPU wheels and permission to download exact weights.

A future provider contract should accept locale, voice ID, prepared display/speech text, pronunciation map, speech rate, optional expression controls, segment boundaries, and approved reference-audio provenance; return audio, sample rate/duration, provider/checkpoint revision, resource measurements, and explicit errors. Unsupported locale, missing voice, rights, or quality failure must stop or request an **explicit** approved fallback. Multiple providers are likely because verified language coverage, quality, license, and hardware fit differ by locale. This is an interface proposal, not code or a programming-language commitment.
